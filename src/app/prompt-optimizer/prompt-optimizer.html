Prompt Engineering Best Practices
Do
  • Lead with a concrete role — "You are a senior X" beats "You are helpful."
  • State the task imperatively at the top, then context, then constraints.
  • Use structural delimiters — XML tags for Claude, system messages for GPT, JSON schema for Gemini.
  • Provide 1–3 few-shot examples — still the highest-ROI technique for accuracy.
  • Specify output shape — JSON schema, Markdown sections, or a fixed template.
  • Add a hedge instruction — "If unsure, say so" reduces hallucination.
  • Cache static prefixes — move stable instructions into cacheable system prompts.
Avoid
  • CoT cues on reasoning models — Claude extended thinking and o-series already reason; "think step by step" wastes tokens.
  • Politeness scaffolding — "Could you please kindly..." adds tokens without improving output.
  • Embedding user input bare — wrap it in tags and instruct the model to treat tag contents as data.
  • Ambiguous pronouns — "summarize this" with no anchor for "this".
  • Format drift — asking for "JSON or similar" guarantees neither.
  • Reasoning + JSON in the same response for non-reasoning models — split into two calls or use structured outputs.
